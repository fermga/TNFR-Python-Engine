## Preserve each step instead of a final monolithic report

The old assessor accumulates a tuple/list of compact steps and serializes a
single report after completion. That pattern cannot guarantee a retained
prefix after hard process termination. The new adapter should retain only
the current admitted center/radius in working memory and stream each complete
step through the shared immutable writer, with an exclusive indexed path and
source/protocol association. A 64-KiB maximum per-step serialization is a
compatible way to enforce the 256-MiB/4096-step cap; oversized evidence is an
explicit stop, not permission to omit required fields.

At minimum retain time, duration, initial center/radius, whole tube, strict
Picard margin, all twenty domain margins, local metric error, endpoint
center/radius, index and field/metric/source association. These compact records
can reconstruct the admitted chain, but do not independently recompute every
Taylor remainder; retain the frozen implementation and that execution premise.
Never convert projected endpoint boxes back into a new uncertainty radius.

Create an immutable attempt record before launch. Flush each completed record;
if interruption leaves a partial current record, preserve it separately and
count only its completed validated predecessors. On a failed step retain its
failed tube/reason and the last completed state without replacing it by a
later attempt. On timeout or memory stop the supervisor records the resource
failure without executing a new mathematical step. Do not interpret a
complete prefix, an acute endpoint, or a small center residual as a successful
whole protocol. Logging/metadata must fit their own stated cap.
