    TNFR API and execution contracts¶

    Status: Active normative view Version source: package metadata

    This hub owns shared API admission and execution boundaries and the generated operator-contract view. The operator registry owns operator metadata; the linked engine, observation and validation modules own their respective execution paths. A registry change alone does not revise an integrator, diagnostic or certificate contract.

    Responsibility Contract owner Implementation boundary
    Common admission, solvers and named operator contracts This document Shared scalar/clock owners, nodal integrators and operator registry
    Conditional relational dynamics and observations Relational dynamics Selected joint law, snapshot/step reports and capture/transit admission
    Hybrid events and finite execution evidence Operator events Declared schedules, transactions, runtime provenance and REMESH certificate APIs

    For executable calls and examples, use the CLI and SDK guide. Mathematical definitions, hypotheses and proofs remain with the linked theory owners. A serialized declaration or diagnostic report does not bypass live preconditions or certify future stability. For calculations that consume conditional sine reports, the chained-report contract owns primitive re-admission, derived-field rebuilding and source-association limits. Public adapters delegate to those shared consumers. The relational contract index distinguishes complete-state observations, exact collective families, finite maintenance bounds and observations of saved forecasts. Sharing a storage identity or export format does not make their support, law or evidence interchangeable.

    Contract model¶

    Word and operator controls¶

    Word admission rejects unregistered operator identifiers before role checks; operator instances retain their metadata, including Recursivity depth. Grammar context flags use the shared Boolean parser: "false" does not grant initialized form or diagnostic permission, and unknown Boolean strings reject. Context is copied, leaving the caller's mapping unchanged. See the grammar contract.

    validate_sequence, parse_sequence and ValidatedSequence default to the shared core word contracts. String validation delegates to the same GrammarValidator checks used by typed execution, including causal debt and prior Coherence; a different input representation cannot bypass these checks. String words carry default operator metadata only. Use actual operator instances when, for example, Recursivity depth matters.

    The explicit context {"compatibility_profile": "legacy"} adds the historical adjacency and THOL-terminal preferences. validate_sequence and parse_sequence also accept that keyword directly, taking precedence over the context value. Both profiles retain the shared core checks; neither establishes live admission, trajectory stability or every manuscript sentence prescription. Callers requiring those additional preferences must select legacy explicitly. Both profiles reject violations of the shared causal checks. parse_sequence raises on rejection; validate_sequence returns its structured outcome.

    TNFR.explain_sequence(operators, context=...) reports this same word policy, ordered English display names in operators, its selected compatibility_profile and compact glyph notation, such as AL → IL → SHA. Lead reader-facing explanations with the English names. It accepts registered names or simple glyph codes, not arrow expressions, apostrophe spellings or bracket syntax as individual tokens. Invalid context yields valid=False with no selected profile; unknown operator identifiers raise. The report explicitly leaves manuscript syntax, live state and trajectory checks unassessed. Context is a declaration, not observed initialization or trigger evidence.

    GrammarValidator.validate and collect_grammar_errors consume the same immutable outcomes from GrammarValidator.validate_checks; diagnostic text does not decide whether a check passed. Strings use shared identifier normalization; supplied operator objects retain their metadata, so unknown identifiers report SYNTAX and Recursivity depth remains subject to U5. run_structural_validation uses these errors for its word status. Omitting the sequence skips word validation; live U3 admission and temporal U6 evidence remain separate obligations. structural.run_sequence observes the target's actual admitted signed form when determining initialization context; a caller flag cannot promote zero or invalid form into permission. It records the last completed operator only after that invocation succeeds.

    Persistent grammar state. Shared require_grammar_state admits stored glyph_history as an ordered list, tuple or deque of registered identifiers. Strings, mappings, sets, unknown tokens and explicitly stored None reject; one-shot iterators reject without consumption. Omit an absent history key, or materialize a valid owned sequence before execution. Present U2 debt must be a nonnegative integer excluding Booleans, and prior-Coherence state must be Boolean. Invalid present state cannot fall back to a shorter trace. The stored operator-step index likewise requires a nonnegative non-Boolean integer; only a missing index falls back to the retained trace length. Only absent bookkeeping is reconstructed from retained history; this cannot recover evicted facts. Deliberate full-trace replacement uses the shared reset helper; restoring a snapshot preserves its valid persistent context. on_applied_glyph delegates to the shared occurrence recorder: it normalizes glyph codes and updates the index, debt and prior IL while preserving deque bounds or unbounded list retention. Tuple traces become unbounded lists. This helper records a caller-supplied occurrence; it neither executes nor authenticates an operator. Do not record an already runtime-recorded action twice.

    read_grammar_state builds a fresh immutable view of canonical history codes, debt, prior Coherence and operator index. Recording admits each retained identifier once; it does not cache permission across mutations. History readers, repetition scores, hysteresis and direct Mutation/Dissonance context readers use shared admission, so equivalent supported names and codes give the same decisions. Malformed authoritative history cannot be hidden by a diagnostic shortcut. Graph validation retains its TNFRValueError error envelope.

    Native batches pre-admit consumed grammar context and lag counters before incrementing counters. Lag limits/counts reject Boolean, fractional or invalid values, and the hysteresis window uses shared integer admission. Grammar's enabled uses shared Boolean parsing. Lag resets follow the glyph actually applied, including grammar substitution; a blocked AL proposal replaced by IL does not reset since_AL. _choose_glyph applies the same grammar to forced candidates but neither increments counters nor executes them. Native batches remain sequential: a later operator failure can retain earlier completed operations and policy bookkeeping; this is not the atomic-stage contract. Mutation proposal screening and execution share raw authoritative-alias and signed-form certificate admission. Explicit invalid EPI cannot be replaced by a secondary alias or turned into missing temporal evidence. Recorded abstention clocks must be valid represented real values. Mutation admits raw authoritative phase and active proposal scalars before conversion. Boolean/nonreal values, nonfinite values and nonzero values lost to zero reject; direct graph rejection precedes adapter caching. The shared proposal preserves the consumed pressure's signed zero after admission. An explicit fixed shift still leaves dynamic proposal arguments unconsumed; the independent temporal/capacity gate remains required. Valid phase wrapping and public/direct/staged execution boundaries are unchanged. Native batch proposals resolve supported English names, tokens and glyph codes through the shared identifier owner before Mutation screening and lag accounting. Emission/Reception counters and Mutation abstention records therefore agree across those spellings, including with canonical grammar disabled. Unknown proposals retain the selected grammar rejection/substitution policy; this is not whole-batch prevalidation or rollback of an earlier executed prefix.

    With glyph execution enabled, runtime.step runs the same batch preflight before creating history, reserving an invocation ordinal or invoking callbacks. It re-admits at consumption after callbacks and pressure refresh. Disabled glyph execution does not consume lag limits or grammar policy. This covers the supplied batch configuration/context, not arbitrary callbacks or a full-step transaction. A late failure can retain observations and its invocation ordinal.

    Soft repetition thresholds GRAMMAR.force_dnfr and force_accel and consumed normalized scores admit original represented-real values in [0,1]; Boolean, text, nonfinite or lost nonzero values reject. Explicit malformed fallback operators reject. Context parameters must be mappings: optional constructor None remains absent, whereas explicitly malformed graph-owned configurations reject before defaults. Empty graph mappings retain the documented default overlay. These checks preserve the supplied normalization/selection policies; they do not infer global maxima from local input or derive a controller. Repeat checking and its error context reuse one fresh admitted history view, without a second permissive interpretation of the retained identifiers.

    Selector pressure/acceleration ratios use shared checked division on scalar, vector and worker paths. Nonfinite quotients and nonzero quotients rounded to zero reject before threshold comparisons. Valid represented ratios remain unclipped; a zero supplied normalization maximum retains its unit-divisor convention. This rejects unrepresentable observations rather than selecting an operator from an invented zero.

    The native selector runs at an outer call's left boundary. Lag counts measure decision batches, internal integration substeps add none, and dt=0 still allows operator events. The clock comparison shows that additional outer decisions can change the physical endpoint at the same final time. Numerical comparisons must retain their declared event schedule and other per-call policies; apply_glyphs=False skips only the glyph batch, not phase/capacity policies or all runtime bookkeeping.

    Native execution consumes complete associated state: form, phase, capacity, stored and refreshed pressure, grammar and lag records, adaptation counters, prior rates, temporal observations and target-associated random-stream state. Default selection additionally uses graph-wide capacity and absolute-pressure maxima through Si and normalized pressure. Matching a component's local state or selected operator labels therefore does not establish a closed component law. Reception consumes live neighboring form; Resonance consumes the live U3-compatible subset and its associated form/phase data. Earlier target events can change a later target's branch. Integration consumes event capacities and held prepared pressure; later policies have their own observation boundaries.

    The native dynamics owner derives the scoped selector, ordered-event and complete-call reductions and counterexamples. The collective calculus owns sufficient retained state, correlated enclosures and their composition requirements. The aggregate operator owner states when an actual registered operator descends to a coarse representation and when it does not. These conditional results neither create a public collective executor nor let a summary report replace the source required by a later call.

    A collective prediction must retain the actual request origin, target order, live branches, state associations and relevant memory. Marginal bounds or matching means do not establish their joint realizability. A retained prefix is not a completed call; refreshed diagnostics, lag increments and invocation ordinals may survive a later failure on the sequential native path. Distinguish native rejection, observer interruption, unavailable temporal evidence and atomic-stage rollback. Ideal reductions and asymptotic theorems also retain their own arithmetic premises; they are not bitwise runtime guarantees.

    The following names are not supported GRAMMAR_CANON controls or --grammar.* CLI options: zhir_requires_oz_window, zhir_dnfr_min, thol_min_len, thol_max_len, thol_close_dnfr, and si_high. Remove these options from CLI invocations; arbitrary mapping extensions retain no admission meaning. The shared U4 context and measured Mutation gate own their actual requirements. Words supply their closure explicitly; no sense-index threshold chooses a THOL closure. There is no one-to-one threshold replacement.

    Coupling's four UM_* branch flags and OZ_NOISE_MODE use the same Boolean parser before active-factor resolution and proposals. Transition's NAV_STRICT and NAV_RANDOM retain their stricter Boolean-only domain across public classes, direct glyphs and stages; strings are rejected. Disabling a branch removes only that branch's factor requirements. It does not waive live U3 or other operator preconditions. The operator maps and event contracts specify the execution effects.

    Scoped program compilation and execution¶

    The existing typed tokens, parser/compiler and program executor own the THOL, WAIT and TARGET program syntax used by the specialized CLI sequence route. This is separate from complete-word validation and the atomic operator-stage route. Compilation does not admit a child NFR, choose a branch or install a continuous law. The source comparison retains the wider hierarchical and prosodic proposals with their open premises.

    parse_program_tokens returns owned typed bodies for explicit THOL blocks; plain iterable grouping remains sequential. compile_sequence returns ordered (OpTag, payload) operations. BLOCK_ENTER and BLOCK_EXIT carry immutable BlockBoundary(path, iteration, repeat) metadata identifying nested occurrences and zero-based body repetitions. These markers neither execute a structural operator nor advance time. Consumers of compiled streams must retain them; filtering only glyphs loses program scope. THOLEvaluator retains its iterator interface as an unscoped token view, not the execution representation.

    The THOL opening executes once per block invocation. Each body repetition inherits the enclosing targets; TARGET changes are local to that repetition and are restored at its exit. There is no automatic child-target selection. Before any explicit TARGET, the target is the current graph population at each glyph; TARGET(None) instead captures the population when that token executes. Ordered explicit target collections preserve their supplied order.

    Program construction follows these explicit contracts:

    Input Contract
    Omitted THOL closure force_close=None, or block(..., close=None), adds no glyph. Supply Glyph.NUL explicitly when that action is intended.
    Explicit closure glyph Every supplied registered glyph is emitted after each repetition and remains subject to live admission. Its position does not make it a valid grammatical closure.
    Nested TARGET assignment Targets restore at each repetition exit. Put a TARGET after the block when subsequent operations require that selection.
    WAIT/repeat count Counts must implement the integer-index protocol, be positive and be non-Boolean. Floats, fractions and strings reject, including integer-valued ones.
    Nested or reused group Cyclic ancestry rejects; repeated occurrences of an ordered group remain present. Unordered sets, unknown token fields and malformed glyphs reject.

    max_materialize is a nonnegative integer or None; the default is 1000. The finite bound covers parsed input and expanded operations, including scope markers. play completes syntax admission and compilation before changing graph history. Live targets, grammar and preconditions are still checked during execution; earlier accepted operations and callback effects are not rolled back if a later operation fails.

    Requested program glyphs use the native direct-glyph path and reject blocked requests without substitution, even when the graph's ordinary rejection policy is fallback. That original policy is restored before the step function runs. No future-handler context is invented across changing targets or scopes. The supplied step_fn, or the existing native runtime by default, runs after each actual glyph, including THOL and an explicit final glyph. WAIT requests additional step-function calls. The default step can select more operators and update phase/capacity: WAIT is not an event-free interval, and its count is neither seconds nor a newly derived clock.

    The bounded history["program_trace"] distinguishes supplied program requests from subsequent step-function execution. A glyph/THOL row is appended after successful glyph dispatch and before stepping, with selection_origin set to supplied_program, ordered pre-dispatch targets, event_time, and event_boundary="after_requested_glyph". A later-created node cannot become a recorded target of that earlier dispatch. TARGET rows retain ordered node IDs; WAIT rows describe requested step calls and make no glyph-event claim.

    Rows begin with step_status="pending" and record_boundary="before_step". They become completed/after_step on success, preserving the existing t field as the post-step clock. Failures retain a failed/step_failed row and the original exception; there is no rollback. Requested, started and normally returned call counts are step_calls_requested, step_calls_started and step_calls_completed. A returned call can still fail clock admission. step_origin distinguishes native_runtime from supplied_step_function; neither value enumerates operators selected internally by that function.

    The initial clock and each recorded clock sample use shared finite represented real admission. Missing _t uses the explicit zero convention. Boolean, nonfinite or nonzero unrepresentable clocks reject. If a callback leaves an invalid clock, its effects remain, the row retains its last admitted t, and clock_sample_available=False marks the unavailable current sample. A rejected glyph dispatch creates no completed-glyph row; earlier target effects can still exist on this non-atomic route. Trace truncation and callback effects prevent using missing rows as proof of no event or as a complete execution checkpoint.

    The canonical_example program preset requests Emission → Coherence → Silence (AL → IL → SHA). It is distinct from the SDK's registered basic_activation word. Presets retain their declared actions and contextual admission needs; contained_mutation and coupling_exploration request Contraction (NUL) explicitly. Controls: program admission and execution.

    Unsupported calls and current replacements¶

    The following interfaces are not part of the current API. Use the declared replacement where one exists; no compatibility alias substitutes a different mathematical model. Source recovery belongs to the recovery index.

    Unsupported interface Current replacement or scope boundary

Use diagnose_network(actual_graph) or physics.fields.compute_unified_telemetry(actual_graph) with explicit state. The removed option reported fields of a fixed demonstration graph, not the validated word or its execution.
    tnfr.operators.algebra.validate_identity_property, validate_idempotence, validate_commutativity_nul Use the actual operator event contracts and compare the same admitted transformations.     tnfr.secure_config Import the same implementations from tnfr.config.security.

    Shared operator requirements¶

    Every canonical operator has:

    • a lowercase English execution token, a public display/class name, and an internal glyph;
    • one primary nodal-equation channel;
    • node or network scale;
    • a direct-effect direction;
    • a verifiable postcondition;
    • independent grammar and state preconditions.

    The channel classification does not replace grammar roles. For example, Mutation acts primarily on phase while also being a U2 destabilizer and U4 transformer.

    Scale is the U5 fractality axis: node acts at the current fiber/level and network denotes the multi-scale REMESH echo. It is not an execution-footprint field. Coupling remains node-scale on this axis even though one application may write neighbouring phases and edge support; those overlaps belong to the separate stage contract.

    Mathematics backend selection¶

    get_backend resolves an explicit name, then TNFR_MATH_BACKEND, then tnfr.backend_config.get_config().math_backend. The service default is auto. Automatic selection tries GPU-capable adapters in JAX, PyTorch, NumPy order, then repeats that order for any available adapter, including CPU adapters. An explicit numpy request selects NumPy. A registered but unavailable named adapter falls back to NumPy; unknown names raise LookupError.

    MathematicsBackend includes is_gpu_available(), get_device_name() and get_backend_info() alongside its array operations. Its typing declarations retain that interface and the canonical core.exceptions.BackendUnavailableError identity. Backend selection supplies a numerical implementation, not an evolution law; reproducibility records must identify the adapter actually used. The PyTorch adapter copies read-only NumPy arrays before conversion because tensors cannot preserve their write protection. Writable arrays retain the existing sharing behavior when dtype/device permit; native tensor conversion preserves identity and autograd when no conversion is needed. The NumPy adapter delegates general matrix exponentials to the required SciPy dependency. If SciPy is unavailable, that operation raises BackendUnavailableError; a possibly defective eigenvector decomposition is not substituted for the exponential. Other NumPy array operations remain available.

    register_backend validates a complete registration before changing factories, aliases or instantiated adapters. Canonical names and aliases cannot shadow one another, including with override=True; empty names and the reserved selection name auto reject. A canonical override replaces its factory and invalidates its instantiated adapter; unmentioned aliases remain. An alias override may retarget an existing alias. A rejected proposal leaves the registry and instance cache unchanged.

A supplied partial orthonormal family returns only its projection coefficients.

    Composite EPI regularity trends admit finite represented-real observations, including those computed from BEPI, and nonnegative represented tolerances. MathematicalDynamicsEngine and ContractiveDynamicsEngine likewise own their admitted generators and return detached generator observations. Reconstruct the engine to change that law; editing the original input or returned array does not change its evolution.     Auxiliary spectral-expectation contract¶

    SpectralExpectationOperator evaluates the Hermitian quadratic form <psi|A|psi>. For a unit-norm state, including the default expectation(..., normalise=True) path, its exact-real value lies in the spectral interval of A; numerical evaluation retains floating-point error. With normalise=False, an unnormalized input instead scales that interval by ||psi||^2: A=diag(2,3) and psi=(2,0) give 8, not a value in [2,3]. Values above one are valid in either mode. This auxiliary value is never the structural coherence C(t), never inherits a [0,1] bound, and never enters C_steps. Payload metadata range="unbounded_real" and bounded=False describe the family of supplied observables; they do not negate the conditional spectral bound for a fixed Hermitian operator and normalized state.

    is_positive_semidefinite requires Hermiticity as well as nonnegative eigenvalues within its tolerance. spectral_weighted_angle uses that shared gate; positive eigenvalues of a non-Hermitian matrix cannot admit a Hermitian angle geometry. The weighted-angle ratio combines binary exponents separately rather than squaring overlaps and multiplying expectations at their original scale. This retains finite scale-invariant angles when those intermediate products would overflow or underflow. Consumed overlaps and positive expectations must still be representable; this does not repair precision lost in dot products or remove the configured absolute null threshold. Operator factories reuse the constructor's Hermiticity and PSD gates and admit original components before backend conversion. The spectral factory's real projection within its imaginary-part tolerance retains the native gradient path. Factory dimensions use the same positive-integer admission as their SDK/CLI consumers; Boolean and floating dimensions reject. Explicit comparison floors and thresholds use the shared represented-real boundary, including rejection of nonzero values lost to materialization. A comparison floor may be negative independently of the supplied PSD spectrum. Construction owns a detached matrix and its matching spectrum. The public matrix and eigenvalues properties, and spectrum(), return detached arrays; editing these observations or the original input cannot change the operator or its PSD verdict. Direct property assignment is no longer supported: create a new operator to change the observable and recompute its spectrum together. Construction reuses its admitted matrix snapshot for Hermiticity checks, avoiding redundant backend transfers; native spectral arithmetic retains its gradient path.
