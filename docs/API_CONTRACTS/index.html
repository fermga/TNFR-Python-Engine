    TNFR API and execution contracts¶

    Status: Active normative view Version source: package metadata

    This hub owns shared API admission and execution boundaries and the generated operator-contract view. The operator registry owns operator metadata; the linked engine, observation and validation modules own their respective execution paths. A registry change alone does not revise an integrator, diagnostic or certificate contract.

    Responsibility Contract owner Implementation boundary
    Common admission, solvers and named operator contracts This document Shared scalar/clock owners, nodal integrators and operator registry
    Conditional relational dynamics and observations Relational dynamics Selected joint law, snapshot/step reports and capture/transit admission
    Hybrid events and finite execution evidence Operator events Declared schedules, transactions, runtime provenance and REMESH certificate APIs

    For executable calls and examples, use the CLI and SDK guide. Mathematical definitions, hypotheses and proofs remain with the linked theory owners. A serialized declaration or diagnostic report does not bypass live preconditions or certify future stability. For calculations that consume conditional sine reports, the chained-report contract owns primitive re-admission, derived-field rebuilding and source-association limits. Public adapters delegate to those shared consumers. The relational contract index distinguishes complete-state observations, exact collective families, finite maintenance bounds and observations of saved forecasts. Sharing a storage identity or export format does not make their support, law or evidence interchangeable.

    Contract model¶

    Word and operator controls¶

    Word admission rejects unregistered operator identifiers before role checks; operator instances retain their metadata, including Recursivity depth. Grammar context flags use the shared Boolean parser: "false" does not grant initialized form or diagnostic permission, and unknown Boolean strings reject. Context is copied, leaving the caller's mapping unchanged. See the grammar contract.

    validate_sequence, parse_sequence and ValidatedSequence default to the shared core word contracts. String validation delegates to the same GrammarValidator checks used by typed execution, including causal debt and prior Coherence; a different input representation cannot bypass these checks. String words carry default operator metadata only. Use actual operator instances when, for example, Recursivity depth matters.

    The explicit context {"compatibility_profile": "legacy"} adds the historical adjacency and THOL-terminal preferences. validate_sequence and parse_sequence also accept that keyword directly, taking precedence over the context value. Both profiles retain the shared core checks; neither establishes live admission, trajectory stability or every manuscript sentence prescription. Callers requiring those additional preferences must select legacy explicitly. Both profiles reject violations of the shared causal checks. parse_sequence raises on rejection; validate_sequence returns its structured outcome.

    TNFR.explain_sequence(operators, context=...) reports this same word policy, ordered English display names in operators, its selected compatibility_profile and compact glyph notation, such as AL → IL → SHA. Lead reader-facing explanations with the English names. It accepts registered names or simple glyph codes, not arrow expressions, apostrophe spellings or bracket syntax as individual tokens. Invalid context yields valid=False with no selected profile; unknown operator identifiers raise. The report explicitly leaves manuscript syntax, live state and trajectory checks unassessed. Context is a declaration, not observed initialization or trigger evidence.

    GrammarValidator.validate and collect_grammar_errors consume the same immutable outcomes from GrammarValidator.validate_checks; diagnostic text does not decide whether a check passed. Strings use shared identifier normalization; supplied operator objects retain their metadata, so unknown identifiers report SYNTAX and Recursivity depth remains subject to U5. run_structural_validation uses these errors for its word status. Omitting the sequence skips word validation; live U3 admission and temporal U6 evidence remain separate obligations. structural.run_sequence observes the target's actual admitted signed form when determining initialization context; a caller flag cannot promote zero or invalid form into permission. It records the last completed operator only after that invocation succeeds.

    Persistent grammar state. Shared require_grammar_state admits stored glyph_history as an ordered list, tuple or deque of registered identifiers. Strings, mappings, sets, unknown tokens and explicitly stored None reject; one-shot iterators reject without consumption. Omit an absent history key, or materialize a valid owned sequence before execution. Present U2 debt must be a nonnegative integer excluding Booleans, and prior-Coherence state must be Boolean. Invalid present state cannot fall back to a shorter trace. The stored operator-step index likewise requires a nonnegative non-Boolean integer; only a missing index falls back to the retained trace length. Only absent bookkeeping is reconstructed from retained history; this cannot recover evicted facts. Deliberate full-trace replacement uses the shared reset helper; restoring a snapshot preserves its valid persistent context. on_applied_glyph delegates to the shared occurrence recorder: it normalizes glyph codes and updates the index, debt and prior IL while preserving deque bounds or unbounded list retention. Tuple traces become unbounded lists. This helper records a caller-supplied occurrence; it neither executes nor authenticates an operator. Do not record an already runtime-recorded action twice.

    read_grammar_state builds a fresh immutable view of canonical history codes, debt, prior Coherence and operator index. Recording admits each retained identifier once; it does not cache permission across mutations. History readers, repetition scores, hysteresis and direct Mutation/Dissonance context readers use shared admission, so equivalent supported names and codes give the same decisions. Malformed authoritative history cannot be hidden by a diagnostic shortcut. Graph validation retains its TNFRValueError error envelope.

    Native batches pre-admit consumed grammar context and lag counters before incrementing counters. Lag limits/counts reject Boolean, fractional or invalid values, and the hysteresis window uses shared integer admission. Grammar's enabled uses shared Boolean parsing. Lag resets follow the glyph actually applied, including grammar substitution; a blocked AL proposal replaced by IL does not reset since_AL. _choose_glyph applies the same grammar to forced candidates but neither increments counters nor executes them. Native batches remain sequential: a later operator failure can retain earlier completed operations and policy bookkeeping; this is not the atomic-stage contract. Mutation proposal screening and execution share raw authoritative-alias and signed-form certificate admission. Explicit invalid EPI cannot be replaced by a secondary alias or turned into missing temporal evidence. Recorded abstention clocks must be valid represented real values. Mutation admits raw authoritative phase and active proposal scalars before conversion. Boolean/nonreal values, nonfinite values and nonzero values lost to zero reject; direct graph rejection precedes adapter caching. The shared proposal preserves the consumed pressure's signed zero after admission. An explicit fixed shift still leaves dynamic proposal arguments unconsumed; the independent temporal/capacity gate remains required. Valid phase wrapping and public/direct/staged execution boundaries are unchanged. Native batch proposals resolve supported English names, tokens and glyph codes through the shared identifier owner before Mutation screening and lag accounting. Emission/Reception counters and Mutation abstention records therefore agree across those spellings, including with canonical grammar disabled. Unknown proposals retain the selected grammar rejection/substitution policy; this is not whole-batch prevalidation or rollback of an earlier executed prefix.

    With glyph execution enabled, runtime.step runs the same batch preflight before creating history, reserving an invocation ordinal or invoking callbacks. It re-admits at consumption after callbacks and pressure refresh. Disabled glyph execution does not consume lag limits or grammar policy. This covers the supplied batch configuration/context, not arbitrary callbacks or a full-step transaction. A late failure can retain observations and its invocation ordinal.

    Selector preparation and selection hooks also have a live admission boundary. The batch readmits policy, clock, grammar and lag records after preparation and after collecting proposals, before executing a glyph. Both boundaries require the original ordered target population. Preparation may change which lag choices are forced; collected proposals retain their selection boundary and are not recomputed. Lag counters advance once. Replaced lag mappings and history-window settings are consumed from the live context. A rejected hook result does not roll back the hook's own changes or imply an atomic batch. The hook controls exercise this boundary through actual glyph execution and rejected requests.

    tnfr.dynamics.apply_native_operator_batch(G, history, decision_trace=None, epi_trace=None) exposes that same native all-node batch. It resolves the graph's configured selector, returns None and advances no time. It does not refresh pressure or diagnostics, supply past samples, select a target subset or install a scheduler. Default and parametric policies retain their current candidate sets and normalizers; exposing this boundary does not make them generate all thirteen operators. Direct glyph execution retains its existing distinction from public operator classes and atomic stages.

    Optional decision_trace must be an exact caller-owned list. The batch appends frozen NativeOperatorDecision reports without replaying selection or grammar. Their selection describes the evaluated builtin branch (base, hysteresis, score, override and soft filter where consumed), or marks custom selection as opaque. Forced lag choices do not invent an evaluated selector branch. Requests retain their preparation boundary; temporal and grammar admission use the live sequential execution state. The reports preserve that distinction.

    The report records lag origin/counts, the actual Mutation gate certificate or abstention reason, the observed grammar decision and the direct dispatch result. The shared grammar observer distinguishes acceptance, fallback, rejection and alternative-selection failure, including fallback to the same code. Invalid inputs before a decision yield no invented approval. applied_glyph is recorded only after dispatch returns; later bookkeeping may still fail.

    This is a sequential batch: a later failure preserves completed earlier actions and propagates the same exception. The caller's list retains the captured prefix, terminal failure and already computed but unreached proposals where available. A failed dispatch may itself have partial effects; absent applied_glyph does not certify rollback. Preflight failure before admitted targets can leave the trace empty. Reports are neither checkpoints nor authenticated provenance, and custom values retain their opaque scope. See the native participation analysis for the supplied policy, diagnostic and decision-clock boundaries.

    Actual native EPI source observation. The optional epi_trace must be an exact caller-owned list distinct from decision_trace. It receives one frozen NativeEPIBatchObservation around the actual public batch call, including an incomplete call that raises. Return value, selector preparation, lag advancement, grammar, dispatch order and sequential failure semantics remain unchanged. The default performs no full-population EPI captures. These observations are exposed through tnfr.dynamics and defined in tnfr.dynamics.native_epi_source.

    NativeEPIEndpoint retains ordered nodes, node_storage_ids, exact_epi, exact_time and unavailability_reasons. EPI uses the shared signed scalar binary64 embedding, including uniform-real BEPI; fractions encode that admitted representation, not arbitrary-precision raw input. Missing, invalid or richer non-scalar form makes observation unavailable without adding a native action precondition. Storage identities associate this local capture; they are not portable node identity or authenticated provenance.

    Each NativeEPIDispatch records the actual dispatch index, target and glyph, whole-population before/after, returned and failure_type. Its exact_increment is the represented endpoint difference where available. An abstained or None request creates no dispatch entry; an action preserving EPI creates a zero increment, even if it changes other structural channels. A raised dispatch can retain measured partial effects and returned=False.

    The batch contains initial, final, dispatches, completed, failure metadata, available and clock_preserved. When all endpoints retain the same ordered population/storage and captured clock, it supplies exact_net_increment, exact_dispatch_increment, exact_dispatch_variation, exact_outside_dispatch_increment, exact_outside_dispatch_variation and the individual exact_outside_dispatch_increments. These are vector sums of exact represented differences. Failed-prefix arithmetic can be available while completed=False; successful execution can have unavailable observations. Changed population/storage, changed or unreadable clock, or unavailable EPI leaves whole-batch totals unavailable rather than inserting zeros.

    An unexpected failure of post-dispatch recording marks capture incomplete. If the primitive returned, its native history cleanup, interval receipt and waiting bookkeeping still complete before the observation error propagates; later targets are not executed. If the primitive or its existing bookkeeping fails, that original error takes precedence. Missing capture cannot be relabelled as an outside-dispatch change or a complete source.

    Outside-dispatch changes include selector/grammar/hook effects between captured boundaries; they are not attributed to an operator. Zero net residual can hide cancelling gaps, and endpoint variation misses an internal round trip. Mutable dispatch registrations and glyph names do not authenticate a canonical map. The record contains no rate, creates no temporal samples or receipt, and cannot activate Mutation. The restricted producer below owns its own positive interval and immediate live admission. See the source analysis.

    Restricted positive-window native source. The opt-in tnfr.operators.execute_native_positive_window(graph, *, duration, candidates=None, method=None, n_jobs=None, mutation_kwargs=None) executes a real positive interval, one terminal native batch and eligible canonical ZHIR responses. It accepts no detached source/report/certificate input. The supplied order differs from the ordinary runtime's batch-before-flow order; the existing native API is unchanged.

    The interval requires the canonical default nodal integrator, zero stored pressure, no Gamma or extended dynamics, and fixed ordered node/storage identity. Form, phase, capacity and support are held during that interval. The actual flow executor advances its declared clock and records its boundaries; a timestamp assignment cannot substitute for it. The terminal batch requires the admitted builtin selector, enabled grammar with rejection mode "raise", and unchanged direct dispatch bindings. Its live grammar, AL/EN waiting priority, sequential order and histories remain in force. Native history is the graph-owned exact dictionary graph.graph["history"], retained by identity; absence creates an empty dictionary. No external history argument or dictionary subclass is admitted by this restricted route. Source acceptance requires complete scalar capture, unchanged terminal clock, contiguous endpoints and zero outside-dispatch variation, not just zero residual.

    The source retains the actual flow execution and native observations separately; native actions are not represented as atomic schedule stages. Growth records exact represented signed endpoint changes divided by the declared positive duration, with separate flow, jump and variation accounting. The interval is (s,t], including the terminal jumps. These values are historical reports; only the private current production scope can bind a fresh response snapshot. They create no continuous secant. Form-writing native actions retain their ordinary history invalidation.

    The returned NativePositiveWindowDispatch exposes source_result, growth, candidates, decisions, selected_targets and optional stage_result; executed means a supplementary phase stage occurred. NativePositiveWindowSource retains flow_result, native_batch, native_decisions and the initial/flow endpoints. NativePositiveWindowGrowth carries the exact interval and vector balance. The growth source is native_positive_window_net_growth; trigger telemetry uses native_positive_window_time, distinct from schedule growth.

    Candidates default to all initial nodes in order; an explicit set is a nonempty unique exact tuple. Each candidate must independently pass strict exact growth, capacity/floor, live grammar and unused-window admission. The shared hybrid _operator_growth_mutation_end watermark retains successful consumed endpoints across this route and the supplied-schedule consumer. Native ZHIR, if actually returned, has precedence over a supplementary response on that target. It cannot acquire a crossing continuous secant in this restricted one-batch zero-flow source; the precedence guard is not evidence of general source competition. Empty selection retains the source and adds no empty phase stage, ZHIR event or hybrid receipt.

    Initial request and domain admission precede source execution; later readmission can fail after actual source effects. The flow executor retains its own failure boundary; native failure preserves elapsed flow and the completed/partial native prefix. An incomplete or unavailable source grants no response. After source completion, eligibility and response have a separate graph transaction: their failure restores the completed source state. External callback effects are outside graph rollback. This is not the source-and-response atomicity of the supplied-schedule consumer. See the restricted source analysis.

    Finite-duration Emission proposal. The opt-in execute_emission_episode(graph, targets, *, duration, method=None, n_jobs=None, window=None) executes a distinct AL episode. It is an explicit constitutive extension: the primary coordinate action follows the AL translation family, while counting one duration-bearing episode as one occurrence is a declared lifecycle choice. Ordinary instantaneous AL and the zero-flow native interface retain their contracts. See the proposal and its assumptions.

    Targets are a nonempty unique exact tuple. Each has positive admitted capacity and pressure, strict AL entry/completion state, and its own enabled grammar in rejection mode "raise". Duration is positive and uses the live structural clock. An already activated target must retain a countable AL lineage; missing lineage cannot certify a new counted episode. Completion checks preserve that lineage. Every nonzero form row must belong to a target; nonparticipants have zero row. The canonical nodal integrator holds pressure, capacity, phase and support, with Gamma absent. A prospective target gain duration * nu_f * DeltaNFR is compared against the shared AL proposal. Clipping or a represented endpoint mismatch rejects the episode; a measured increment cannot be used to fit its own gain.

    The integrator supplies the EPI change and real physical boundary samples. Completion commits shared AL activation lineage, source-glyph provenance and exactly one grammar occurrence, without another AL form write. Physical history therefore remains valid. Native waiting counters are unchanged, matching the separate public-operator semantics. The episode is atomic on graph-owned state; failure restores its entry state. It is not an interruptible persistent action, and external callback effects are outside graph rollback.

    EmissionEpisodeResult retains ordered population/targets, the actual flow_result, prospective rates/gains and represented EPI endpoints. Numerical substeps count within one episode; separately invoked episodes count separately. Actual solver derivative diagnostics remain observable and may depend on the subdivision. Neither a report nor equal endpoints authenticate another execution.

    Successive episodes retain actual physical history across pressure-only IL/OZ actions. A subsequent graph-backed THOL reads active history. Public/staged/native routes retain their own grammar admission and the optional strict public/staged gate remains separate; direct glyph dispatch alone is not full grammar admission. The selected finite window remains part of the observation. Its signed pressure result need not admit another positive-rate AL episode. Rejection of that later episode restores its own entry state, preserving completed THOL. See the causal composition and boundaries.

    The same actual source can feed the existing eligible THOL dispatcher and admitted child creation. Its returned parent/child association can supply an explicit UM request, followed by actual EN/RA participation. Birth supplies neither contact nor inherited child grammar/physical history. The three-branch integration separates child input from UM's other effects and tests the child's own later actions; invocation times and source selection remain supplied policies.

    execute_native_emission_window(graph, emission_targets, *, duration, candidates=None, method=None, n_jobs=None, episode_window=None, mutation_kwargs=None, selector_acceleration_source="solver_diagnostic") owns an actual episode, one sequential native batch and eligible supplementary ZHIR responses. These are premises of the arithmetic models, not physical identifications. cayley_diffusion_action preserves support-derived exact stationary Fourier modes, including disconnected supports. Unrepresentable positive clock products or nonfinite Fourier intermediates reject explicitly; the calculation remains a floating evaluation of a supplied fixed circulant law.

    Finite-field arithmetic normalizes integer/index elements to Python integers before operations and requires 0 <= element < q; powers require nonnegative integer exponents, and power-set orders are positive integers. For built-in field arithmetic, normalized periods can reuse character values within one invocation while preserving the original summation order. Later calls read the current presentation anew; customized arithmetic and character hooks retain their direct dispatch. OptimizedTNFRPrimality applies the same strict abs(delta_nfr) < threshold policy with and without sieve coverage. The cut must be finite, positive and representable; the default 0.5 separates the prime zero set for its configured weights. Larger cuts may admit composites and do not alter the exact theorem. Returned reports and nested metrics are detached from the cache; subsequent calls do not change previous cache_hit observations.

    Auxiliary spectral-expectation contract¶

    SpectralExpectationOperator evaluates the Hermitian quadratic form <psi|A|psi>. For a unit-norm state, including the default expectation(..., normalise=True) path, its exact-real value lies in the spectral interval of A; numerical evaluation retains floating-point error. With normalise=False, an unnormalized input instead scales that interval by ||psi||^2: A=diag(2,3) and psi=(2,0) give 8, not a value in [2,3]. Values above one are valid in either mode. This auxiliary value is never the structural coherence C(t), never inherits a [0,1] bound, and never enters C_steps. Payload metadata range="unbounded_real" and bounded=False describe the family of supplied observables; they do not negate the conditional spectral bound for a fixed Hermitian operator and normalized state.

    is_positive_semidefinite requires Hermiticity as well as nonnegative eigenvalues within its tolerance. spectral_weighted_angle uses that shared gate; positive eigenvalues of a non-Hermitian matrix cannot admit a Hermitian angle geometry. The weighted-angle ratio combines binary exponents separately rather than squaring overlaps and multiplying expectations at their original scale. This retains finite scale-invariant angles when those intermediate products would overflow or underflow. Consumed overlaps and positive expectations must still be representable; this does not repair precision lost in dot products or remove the configured absolute null threshold. Operator factories reuse the constructor's Hermiticity and PSD gates and admit original components before backend conversion. The spectral factory's real projection within its imaginary-part tolerance retains the native gradient path. Factory dimensions use the same positive-integer admission as their SDK/CLI consumers; Boolean and floating dimensions reject. Explicit comparison floors and thresholds use the shared represented-real boundary, including rejection of nonzero values lost to materialization. A comparison floor may be negative independently of the supplied PSD spectrum. Construction owns a detached matrix and its matching spectrum. The public matrix and eigenvalues properties, and spectrum(), return detached arrays; editing these observations or the original input cannot change the operator or its PSD verdict. Direct property assignment is no longer supported: create a new operator to change the observable and recompute its spectrum together. Construction reuses its admitted matrix snapshot for Hermiticity checks, avoiding redundant backend transfers; native spectral arithmetic retains its gradient path.

    NodeNX, create_math_nfr, the dynamics runtime and the CLI expose the canonical names spectral_operator, spectral_expectation_threshold and spectral_operator_expectation. Every result payload contains value, threshold, passed, metric_kind, range, bounded, provenance, canonical_coherence_certified=False and records_to_C_steps=False.

    Historical coherence_operator, coherence_threshold, coherence_value, coherence_passed and runtime history keys remain explicit compatibility aliases. They mirror the same auxiliary spectral value and carry no C(t) meaning. Supplying contradictory canonical and historical inputs is rejected.

    The CLI accepts --math-spectral-expectation-spectrum, --math-spectral-expectation-floor and --math-spectral-expectation-threshold. The former --math-coherence-* spellings remain accepted as aliases.
